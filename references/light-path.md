# 轻路径

做一页或一个流程时走这条路：新建单页或单个流程，沿用已定方向继续做，或者整页范围内的重做。全程只读入口、本文件和入口为这类页面点名的那一两份文件；入口“按需再读”表里的参考，等对应的情况出现了再读，不预读。

用户要比较几个方向或版式、要把概念和主视觉做到极致时，按入口加深，加深只改变第 1 步怎样定方向，第 2–5 步照旧。任务属于入口路径表里的其他行时，照那一行走。

## 1. 动手前写六行

写在回复或设计说明里，不另起文档。每行写具体选择；写不出具体选择的那一行，就是这一页还没想清楚的地方。

1. **用户与任务**：谁，在什么设备上，来做什么。主视口定一个。
2. **主角与主动作**：首屏和每个关键状态各一个主角、一个主动作；其余动作写明怎样降级。
3. **基线与偏离**：这个品类里用户已经期待的结构，照用；再写本页哪一处不照做，以及来自这个产品的理由。说不出理由就不偏离。
4. **方向**：一句话，第一眼的感受和整页围绕什么展开。入口为这类页面点名的文件要求别的产物时，写在这一行下面。
5. **字体、色彩、主视觉**：具体字族和字重关系；底色、强调色、由它们派生的选中与描边各是什么，颜色来自这个产品的什么；主视觉是哪张图或哪个图形，来自项目已有、公开素材、生成还是代码。
6. **动效与状态**：主操作的反馈、一处状态切换、首次进入各怎么动；主流程会经过哪些状态，例如空、加载、出错和成功。

用户或你自己说出“高级”“简洁”“精致”这类词时，先换成上面某一行里看得见的决定，换不出来就不当理由。

需要用户确认时，把第 2–5 行压成三四行发出去，结束这一轮；用户说了“你定”“直接做”或无人值守时，写完接着做。全程只确认这一次。用户只想先看首屏时，只做这一个方向的首屏。

## 2. 实现

- 先做完这一页或这条流程的主要状态，再考虑其他页面。主流程从入口走得到结果，不只做一个漂亮的默认状态。
- 需要关键素材时先选定或做出它，再围绕它排文字和操作，不等布局填满以后再补图。
- **分组先用空间，最后才用线。** 同一组靠得近、组和组之间留开；还分不清时拉开字号或字重，再不够才换底色。线和框只留给可点的整块卡片、输入框和需要浮起的面板：加框的区域里不再摆加框的小块，留白已经分开的地方不补线，同一处分隔不画两次。
- 颜色、字号、间距和圆角先定成少量变量，后面一律引用。已有项目用它现成的变量、组件和库，问题从源头修，不把无关的代码重构混进来。
- 内容按真实产品写：名称、数字和时间有长有短，按钮写按下去会发生什么。模拟数据、没接入的动作和生成的图片写进交付说明，不写在画面上；不伪造成交、评价和指标。
- 没有工程约束的独立小样用一个 `index.html`，样式和脚本写在里面。

## 3. 截图，看，改

攒一批改动再截，不是每改一处截一次：

```text
node <skill>/scripts/shoot.mjs index.html --size desktop,mobile --out shots
```

只做一端时只截那一端，用 `--size desktop` 或 `--size mobile`。要看操作之后的画面，加 `--steps "名字: click .open; fill #name 内容"`，一组出一张。宿主提供 [工具](tools.md) “宿主工具”一节列出的专用截图工具时用宿主的；通用的浏览器截图工具替代不了它，因为不带下面这些检查。其他用法在那份文件和 `--help` 里，用到再查。

- **工具报出来的逐条改掉。** 它会查控制台错误、横向溢出、加载失败的图片、文字对比度、过小的字、过紧的行高、停在透明的内容、手机上会触发页面放大的输入框、要滚动才够得着的弹窗按钮，以及用边框分组过多。标准写在工具里，不用背；和画面无关的接口报错记进交付说明，不为此改业务代码。
- **提示清零以后亲自看图。** 三秒内说不说得出主角和主动作；多行标题、正文和窄屏换行有没有重叠、被裁或孤字；手机上主操作在不在视口里。截图存下来不等于看过。
- **会保存东西的界面走一遍保存、刷新、读回，再走一次失败。** 项目里已有检查交互的脚本时，交付前自己跑一次。
- 只跑项目的类型检查和 lint；生产构建和全量测试，用户要求时才跑。

## 4. 一轮独立评审

新界面和整体改版，自查过截图以后派一个没有制作历史的子 Agent 看一轮，单页也照做，按 [视觉评审派发协议](visual-review.md) 交接。页面有主要操作流程（填表提交、多步流程、会保存东西的操作）时，同一轮按 [轻量 UX 走查派发](ux-review.md) 再派一个。

按报告从影响最大的一条往下改。问题落在哪一类，这时再读入口“按需再读”表里对应的那份参考，然后改。改完自己复看受影响的画面。

宿主不能派子 Agent，或没有能看图的执行者时，对着截图自查，交付时写明“未独立评审”。小改动不派。

## 5. 交付

交付说明写五件事：选定的方向和理由；改了什么，哪些没做、为什么；做了哪些动效；评审结果和主要问题怎样处理的，没派时写原因；证据文件在哪里。建了过程目录时，按 [任务工作区](workdir.md) 核对最终改动，不把过程文件带进正式交付，也不写进 Skill 安装目录。
