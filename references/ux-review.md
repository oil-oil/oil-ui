# 轻量 UX 走查派发（主 Agent 专用）

## 默认什么时候派

新界面有主要操作流程（填表提交、多步流程、会保存东西的操作），或用户要求独立验证可用性时，交付前派一个全新的 UX 子 Agent 做轻量走查，和视觉评审同一轮。纯视觉小改动、方向首屏、没有可操作流程的页面和只有静态画面的评审不派。界面好不好看与任务是否符合直觉，分开验收。

## 交接什么

评审者按 [轻量 UX 走查](ux-reviewer.md) 执行，主 Agent 不读这份评审手册，只交接下面的材料。

必给当前页面入口、主视口、必要的测试凭据或测试文件、安全边界；有运行方式限制也写清。主视口用于说明使用场景，走查者可以使用不同大小的窗口；窗口不同本身不算问题，主 Agent 不为此补做整套检查，只有问题本身与尺寸有关时才在主视口复现。不给原始 `TASK.md`、具体用户案例、预期操作路径、源代码、设计说明或历史问题。提示词用：

`请读取 references/ux-reviewer.md，按照【轻量 UX 走查】执行。只通过真实页面理解产品和用户目标，自主选择一条主要路径操作，记录实际观察到的体验障碍。页面地址、主视口和必要测试材料如下；窗口可不同，仅尺寸相关的问题需要在主视口复现。`

模板路径换成本 Skill 目录下的绝对路径。子 Agent 必须能操作真实页面；只能看截图或源码时，改交静态 UX 走查并标明，不说任务已经走通。它给出的产品理解、任务和路径都是它的观察结果，不是主 Agent 预先布置的脚本。

主 Agent 在走查记录里留下这次隔离调用的标识（子 Agent ID、会话 ID 或运行目录）和证据位置；宿主不暴露标识时，保留能区分主 Agent 与评审者的独立上下文和操作记录。只有主 Agent 自述、无法核对独立执行者的，按自检处理，写明“未完成独立 UX 走查”，不称子 Agent 已评审。

## 收到报告以后

先把每条问题分成可复现的产品问题、测试工具或数据问题、仍待验证的推测；先排除后两类，不用制作意图反驳观察。保留实际路径和证据，修的是入口、反馈、上下文和恢复方式，不只补一段说明。

轻量走查修正后不强制再派 UX 子 Agent；主 Agent 自己完成保存、刷新读回、失败恢复等功能验证，评审报告不能替代这一步。UX 子 Agent 能发现可观察的操作障碍，但不代表真实用户，也不据此推断真实用户成功率、满意度或耗时。
